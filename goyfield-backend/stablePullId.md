# Вычисление стабильного ID круток

Стабильный ID круток - второй по порядку доверия ID круток.

Порядок ID круток следующий:

1. ID из хэша токена
2. Стабильный ID
3. ID профиля круток, переданный клиентом

Записи в БД ID токена и стабильного ID делаются независимо дург от друга, но если существует профиль с ассоциацией к ID
токена, то используется он.

## Стабильный период

Стабильный период - это неделя с ПН по ВС.

### Номер стабильного периода

Номер стабильного периода - это номер недели с момента epoch.

## Получение круток

Клиент отправляет ts последней крутки, от него делается отступ назад в 7 дней, после чего вычисляется начало периода, в
который входит ts с отступом. Крутки получаются до этого начала периода, включительно.

## Группировка полученных круток

Полученные крутки сортируются по времени по возрастанию и группируются по дням, затем по типу баннера, после этого по
периодам.

Крутки, сделанные в текущий период (который не закончился на момент вычисления), игнорируются.

## Вычисление ID для периода

Сначала алгоритм пытается вычислить ID для одного типа баннера, если не получается - для следующего и т.д.

Очередность типов баннеров:

1. Special
2. Weapon
3. Joint
4. Standard
5. Beginner

Для типа баннера получаются сгруппированные крутки по дням. Алгоритм вычисляет хэш круток за **последний** день периода.
Если круток за день не было, он переходит с следующему дню. То есть алгорим идет с ВС по ПН периода.

## Вычисление ID для всех круток

Вычисляются ID для всех периодов, которые есть в крутках (не считая текущий), образуя массив ID.

## Получение записи о профиле по ID

Из БД получается первая запись с ID, который есть в полученном массиве.

Если номер периода полученной записи не совпадает с номером периода запрошенного ID, выбрасывается исключение, т.к.
такое поведение не предусмотрено.

## Запись ID в БД

В БД записывается ID периода с самым большим порядковым номером (т.е. последний полученный период).

## Передача ID на клиент

На клиент передается публичный ID профиля круток.
